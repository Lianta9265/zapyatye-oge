# Архитектура «Запятые ОГЭ»

Сайт статический: каждый раздел имеет настоящий HTML-файл. Переходы — обычные ссылки. Роутера, подмены `history`, серверного fallback и тяжёлых зависимостей нет. Поэтому работают прямые ссылки, обновление страницы, «Назад» и «Вперёд», а также автономное открытие `index.html`.

## Реестр разделов

`site/topics.json` — единый реестр основных тем и подразделов:

| Поле | Назначение |
|---|---|
| `id` | Стабильное имя раздела |
| `title` | Подпись плитки и заголовок страницы |
| `parent` | ID родительского раздела для подразделов |
| `path` | Собственная HTML-страница, путь относительно корня сайта |
| `kind` | `planned`, `collection` или `trainer` |
| `theme` | `teal`, `honey`, `coral`, `plum`, `emerald`, `sea` |
| `caption` | Краткая подпись; для будущих разделов по умолчанию «Раздел готовится» |
| `entry`, `dataset` | Скрипт и набор заданий конкретного тренажёра; у заготовок `null` |
| `assets` | Дополнительные стили, скрипты и данные тренажёра для статической сборки |
| `progressKey`, `journalKey` | Собственные ключи localStorage; у будущих разделов разные |

СПП использует прежний ключ `oge-spp-commas:progress:v2`, в котором журнал находится в поле `errors`. Это намеренное исключение: сохранённые ранее результаты остаются совместимыми. Все будущие темы уже имеют отдельные зарезервированные пространства прогресса и ошибок. Главная страница и страницы-заготовки не запускают скриптов и вообще не обращаются к localStorage.

## Как добавить тренажёр

1. Разработать код и набор заданий нового раздела в отдельных файлах, не меняя `app.js`, `core.js` и `data/corpus.*` СПП. Например: `trainers/vvodnye/app.js`, `trainers/vvodnye/styles.css`, `trainers/vvodnye/data.json`.
2. Заменить HTML-заготовку нужного раздела собственной страницей тренажёра. Указать относительные пути к его ресурсам и добавить ссылку «На главную». Для подраздела сохранить также «К обособлению».
3. В реестре заменить `kind` на `trainer`, заполнить `entry`, `dataset`, `assets` и актуальную подпись `caption`. Использовать только собственные `progressKey` и `journalKey`.
4. Выполнить `node scripts/build-pages.cjs`, затем тесты. Генератор обновляет главную, коллекции и заготовки; HTML с `kind: trainer` он не перезаписывает.
5. Выполнить `node scripts/build-site.cjs`. Новые ресурсы из `entry`, `dataset` и `assets` автоматически попадут в `dist/`.

Нельзя использовать ключи СПП для чужого прогресса, очищать всё localStorage или загружать код другого тренажёра на главной странице. Разделы остаются независимыми.

## Страницы

- `index.html` — главное меню.
- `spp.html` — сохранённый тренажёр СПП, дополненный постоянной ссылкой на главную.
- `topics/*.html` — основные темы и «Обособление».
- `topics/obosoblenie/*.html` — шесть подразделов.
- `site.css` — оформление меню, заготовок и ссылки возврата. Его правила не меняют существующие элементы тренажёра, кроме отступа прокрутки под дополнительной навигацией.
- `controls.css` — финальная полировка кнопок и подписи; подключается после базовых стилей во всех разделах.
- `compact.css`, `panel.js` — компактная панель СПП и раскрывающиеся мобильные команды. Подключаются только в `spp.html`; отдельный контроллер не работает с localStorage и проверкой ответов.
- `scripts/browser-qa.cjs` — изолированная проверка реальным установленным Chrome, размеры и скриншоты. Зависимость `playwright-core` используется только этим инструментом; в `dist/` и страницы сайта не включается.
- `styles.css`, `data/corpus.*` — прежние базовые стили и корпус СПП; сохранены побайтно.
- `core.js` — проверка СПП, включая отдельные подтверждённые связи необязательных предлогов с союзными словами и безопасный пересчёт журнала. Ключи корпуса и логика запятых не изменены.
- `app.js` — существующий интерфейс с допустимой подсветкой предлогов и учётом высоты увеличенной панели при сохранении места.

## GitHub Pages

Сайт рассчитан на адрес вида `https://<имя>.github.io/zapyatye-oge/`. Все внутренние ссылки, ресурсы и кнопки возврата относительные. Пути, начинающиеся с `/`, не используются. На диске и на сервере должны сохраняться имена файлов и структура каталогов.

`node scripts/build-site.cjs` создаёт статическую папку `dist/` с `index.html`, `.nojekyll`, всеми страницами и нужными ресурсами. Исследовательские HTML-снимки, `node_modules`, кэш и локальные служебные файлы в неё не копируются. Для просмотра сборки по запланированному пути: открыть `http://127.0.0.1:4173/dist/index.html` при работающем локальном сервере.

После разрешения преподавателя содержимое `dist/` можно опубликовать в репозитории `zapyatye-oge` и выбрать соответствующий источник GitHub Pages. Сейчас ни репозиторий, ни публикация, ни автоматическое развёртывание не создавались.

Переход с локального адреса на GitHub Pages меняет origin браузера. Старый локальный прогресс автоматически между разными доменами не переносится; совместимость в рамках прежнего локального адреса сохранена. Полноценный перенос между устройствами или доменами — отдельная функция, сейчас не реализована.
